# 화면 이전 체크리스트

Streamlit 앱(`app.py`)의 동작을 웹 버전으로 옮기면서, **놓치기 쉬운 규칙을 빠뜨리지 않으려고**
만든 목록입니다. 화면 하나를 옮길 때마다 여기 항목을 하나씩 대조합니다.

세션이 바뀌어도 어디까지 했는지 남기려는 목적이므로, 옮긴 항목은 `[x]`로 표시합니다.

## 공통 원칙

- **업무 규칙은 DB에 있습니다.** `register_usage`, `add_repair_return` 같은 SQL 함수와 RLS 정책이
  그대로 유지되므로, 화면이 무엇이든 재고 계산·권한 검사는 동일하게 동작합니다.
  화면에서 다시 구현하지 말고 **기존 RPC를 그대로 호출**할 것.
- 검증 스크립트 `verify_stage3.py`는 DB 계층을 시험하므로 웹 버전에서도 **그대로 재사용**합니다.
- 권한은 로그인 사용자의 `user_metadata.role` (`관리자` / `일반`)로 판단합니다.
  화면에서 숨기는 것은 편의일 뿐, 실제 차단은 RLS가 합니다.
- 최상위권한자는 `gyjeong@hanjin.com` 한 명이며, 감사 로그 조회만 해당합니다.

### 옮기지 않는 것 — 로그인 잠금

Streamlit 앱에는 "비밀번호를 10번 틀리면 5분 잠김" 기능이 있지만 **웹 버전에는 넣지 않습니다.**
정적 페이지에는 횟수를 세어둘 서버가 없기 때문입니다.

**실질적인 손실은 없습니다.** Streamlit 배포본에서도 이 잠금은 **이미 동작하지 않고 있습니다.**
프록시 뒤에서 돌아가는 탓에 접속자를 구분할 수 없어서, 잘못 잠그는 것보다 안 잠그는 쪽이
안전하다고 판단해 꺼둔 상태입니다 (`auth.py`의 `_usable_ip` 주석 참고).
양쪽 다 무차별 대입 방어는 Supabase 자체 rate limit과 비밀번호 강도에 의존합니다.

- [x] 컨베이어 ID 입력칸
- [x] 입력이 비어 있으면 아무것도 표시하지 않음
- [x] `find_boq` RPC로 검색 — **띄어쓰기·대소문자 무시**, PLC 그룹 포함/미포함 형태 둘 다 검색됨
- [x] 스펙이 없으면 안내만 표시하고, **교체이력 검색은 그대로 진행** (BOQ에 없는 설비도 이력은 있을 수 있음)
- [x] 스펙이 있으면 표로 표시
- [x] **스펙이 있으면 이력 검색에 "검색어"가 아니라 "BOQ에서 찾은 컨베이어 ID"를 사용**
      (PLC 그룹 포함 형태로 검색해도 이력은 PLC 없는 원래 ID로 남아 있음)
- [x] 교체이력: 해당 설비 + `구분 = 출고`, 일자 내림차순
- [x] 이력 컬럼: 일자 / 부품명(규격) / 수량 / 자재 출처 / 문제 / 조치 / 부품메모 / 비고
- [x] 이력이 없으면 "이 설비의 교체 이력이 없습니다"
- [x] 이력 엑셀 다운로드 (파일명: `{검색어}_교체이력.xlsx`)

**주의:** 이력의 `equipment_id` 중에 `○` 같은 기호가 붙은 값이 있습니다. 정확히 일치시키는
방식이라 그런 기록은 검색되지 않습니다. Streamlit 앱도 동일하므로 **동작 차이는 아니지만**,
나중에 데이터 정리 대상입니다.

## 2. 자재 목록  ✅ 완료

**데이터 정리는 끝났습니다 (2026-08-06~07).** 부품명이 같던 자재를 합쳤고
(창고번호는 `16, 41, 42`처럼 한 칸에 모음), 전기 자재의 부품명·설치위치·구분이
한 칸씩 밀려 있던 것도 바로잡았습니다. 자세한 내용은 `자재이관_주의사항.md` 참고.

- [x] 전체 목록 표 (필터 · 정렬)
- [x] **구매필요 = 표준재고 − 현재재고** 컬럼을 매번 계산해서 붙임
- [x] 총 건수 표시
- [x] 엑셀 다운로드 (화면에서 필터한 결과 기준)
- [x] 수정/삭제는 **관리자만** 보임 (일반 사용자에게는 안내 문구)
- [x] 감사 로그는 **최상위권한자에게만** 표시 (최근 200건)

**Streamlit과 일부러 다르게 한 것:**
- 수정 창을 여는 방법이 행마다 붙은 버튼이 아니라 **행 클릭**입니다.
  구매 요청 화면과 같은 이유입니다 — Streamlit은 행 개수만큼 버튼을 그려야 했지만,
  여기서는 표가 행 선택을 지원합니다.
- 그래서 **"카테고리·부품명으로 먼저 좁히기"와 "30건 넘으면 안내만 표시"를 옮기지
  않았습니다.** 둘 다 버튼을 수백 개 그리지 않으려고 만든 우회책이었습니다. 표의 컬럼
  제목 아래 필터 칸이 이미 같은 일을 하고, 페이지로 나눠 그리므로 건수 제한도 필요 없습니다.

## 4. 사용(출고) 이력  ✅ 완료

- [x] 출고 이력 표 (필터 · 정렬 · 엑셀)
- [x] 행을 고르면 그 설비 ID로 **BOQ 검색 화면으로 이동**
- [x] 카테고리로 부품 목록 좁히기
- [x] **자재 출처 선택** — 보우 / POSCO / 한진 SPARE / 한진 구매품 / BEUMER / 직접 입력
- [x] **한진 SPARE · 한진 구매품일 때만 재고 차감 + 수리 건 자동 생성** ⚠️ 핵심 규칙
- [x] "직접 입력"은 목록에 없는 값이라 **항상 차감되지 않음**
- [x] "직접 입력"을 골랐으면 옆 칸 입력 필수
- [x] 등록은 `register_usage` RPC 한 번으로 (이력 + 차감 + 수리건이 한 묶음)

**Streamlit과 일부러 다르게 한 것 (은근한 차이가 아니라 의도한 개선):**
- 부품 선택칸의 **값을 부품명이 아니라 자재 id**로 씁니다. 부품명이 같은 자재가 24종
  64건 있어서, 이름으로 되찾으면 늘 첫 번째 것이 골라져 **엉뚱한 자재의 재고가 깎입니다.**
  화면에 보이는 글자에는 창고번호를 붙여 사람이 구분할 수 있게 했습니다.
  (Streamlit 앱에는 이 문제가 남아 있습니다 — 리뷰 2단계 항목)
- 표에서 **'구분' 컬럼을 뺐습니다.** 이 화면은 전부 출고라 값이 늘 같아 자리만 차지합니다.
- 고른 출처가 **재고를 깎는지 아닌지 안내 문구**를 띄웁니다. 재고가 안 줄었다고
  오해하기 쉬운 부분이라 넣었습니다.
