# 화면 이전 체크리스트

Streamlit 앱(`app.py`)의 동작을 웹 버전으로 옮기면서, **놓치기 쉬운 규칙을 빠뜨리지 않으려고**
만든 목록입니다. 화면 하나를 옮길 때마다 여기 항목을 하나씩 대조합니다.

세션이 바뀌어도 어디까지 했는지 남기려는 목적이므로, 옮긴 항목은 `[x]`로 표시합니다.

## 공통 원칙

- **업무 규칙은 DB에 있습니다.** `register_usage`, `add_repair_return` 같은 SQL 함수와 RLS 정책이
  그대로 유지되므로, 화면이 무엇이든 재고 계산·권한 검사는 동일하게 동작합니다.
  화면에서 다시 구현하지 말고 **기존 RPC를 그대로 호출**할 것.
- 검증 스크립트 `verify_stage3.py`는 DB 계층을 시험하므로 웹 버전에서도 **그대로 재사용**합니다.
- 권한은 로그인 사용자의 `user_metadata.role` (`관리자` / `일반`)로 판단합니다.
  화면에서 숨기는 것은 편의일 뿐, 실제 차단은 RLS가 합니다.
- 최상위권한자는 `gyjeong@hanjin.com` 한 명이며, 감사 로그 조회만 해당합니다.

### 옮기지 않는 것 — 로그인 잠금

Streamlit 앱에는 "비밀번호를 10번 틀리면 5분 잠김" 기능이 있지만 **웹 버전에는 넣지 않습니다.**
정적 페이지에는 횟수를 세어둘 서버가 없기 때문입니다.

**실질적인 손실은 없습니다.** Streamlit 배포본에서도 이 잠금은 **이미 동작하지 않고 있습니다.**
프록시 뒤에서 돌아가는 탓에 접속자를 구분할 수 없어서, 잘못 잠그는 것보다 안 잠그는 쪽이
안전하다고 판단해 꺼둔 상태입니다 (`auth.py`의 `_usable_ip` 주석 참고).
양쪽 다 무차별 대입 방어는 Supabase 자체 rate limit과 비밀번호 강도에 의존합니다.

## 1. BOQ 검색  ← 1차 목표

- [ ] 컨베이어 ID 입력칸
- [ ] 입력이 비어 있으면 아무것도 표시하지 않음
- [ ] `find_boq` RPC로 검색 — **띄어쓰기·대소문자 무시**, PLC 그룹 포함/미포함 형태 둘 다 검색됨
- [ ] 스펙이 없으면 안내만 표시하고, **교체이력 검색은 그대로 진행** (BOQ에 없는 설비도 이력은 있을 수 있음)
- [ ] 스펙이 있으면 표로 표시
- [ ] **스펙이 있으면 이력 검색에 "검색어"가 아니라 "BOQ에서 찾은 컨베이어 ID"를 사용**
      (PLC 그룹 포함 형태로 검색해도 이력은 PLC 없는 원래 ID로 남아 있음)
- [ ] 교체이력: 해당 설비 + `구분 = 출고`, 일자 내림차순
- [ ] 이력 컬럼: 일자 / 부품명(규격) / 수량 / 자재 출처 / 문제 / 조치 / 부품메모 / 비고
- [ ] 이력이 없으면 "이 설비의 교체 이력이 없습니다"
- [ ] 이력 엑셀 다운로드 (파일명: `{검색어}_교체이력.xlsx`)

**주의:** 이력의 `equipment_id` 중에 `○` 같은 기호가 붙은 값이 있습니다. 정확히 일치시키는
방식이라 그런 기록은 검색되지 않습니다. Streamlit 앱도 동일하므로 **동작 차이는 아니지만**,
나중에 데이터 정리 대상입니다.

## 2. 자재 목록

- [ ] 전체 목록 표 (필터 · 정렬)
- [ ] **구매필요 = 표준재고 − 현재재고** 컬럼을 매번 계산해서 붙임
- [ ] 총 건수 표시
- [ ] 엑셀 다운로드 (화면에서 필터한 결과 기준)
- [ ] 수정/삭제는 **관리자만** 보임 (일반 사용자에게는 안내 문구)
- [ ] 카테고리 · 부품명 검색으로 좁히기
- [ ] **결과가 30건을 넘으면** 행별 수정 버튼 대신 "더 좁혀달라"는 안내만 표시
- [ ] 감사 로그는 **최상위권한자에게만** 표시 (최근 200건)

### 자재 수정 팝업

- [ ] 부품명(규격)이 비어 있으면 저장 거부
- [ ] **현재재고는 덮어쓰지 않고, 팝업을 연 시점 대비 "차이"만 반영** ⚠️ 놓치기 쉬움
      (팝업이 열려 있는 동안 다른 사람이 출고해도 그 변화를 지우지 않기 위함)
- [ ] 수정 시 감사 로그 기록 (before / after)
- [ ] 삭제 시 감사 로그 기록
- [ ] 삭제가 **참조 위반(23503)** 이면 "입출고 이력이 남아있어 삭제할 수 없습니다"
- [ ] 그 외 오류는 DB가 준 실제 사유를 표시 ⚠️ 두 경우를 뭉뚱그리지 말 것

## 4. 사용(출고) 이력

- [ ] 출고 이력 표 (필터 · 정렬 · 엑셀)
- [ ] 행을 고르면 그 설비 ID로 **BOQ 검색 화면으로 이동**
- [ ] 카테고리로 부품 목록 좁히기
- [ ] **자재 출처 선택** — 보우 / POSCO / 한진 SPARE / 한진 구매품 / BEUMER / 직접 입력
- [ ] **한진 SPARE · 한진 구매품일 때만 재고 차감 + 수리 건 자동 생성** ⚠️ 핵심 규칙
- [ ] "직접 입력"은 목록에 없는 값이라 **항상 차감되지 않음**
- [ ] "직접 입력"을 골랐으면 옆 칸 입력 필수
- [ ] 등록은 `register_usage` RPC 한 번으로 (이력 + 차감 + 수리건이 한 묶음)

## 6. 구매 요청

- [ ] 부품 선택 시 표준재고 / 현재재고 표시
- [ ] 요청 등록 (요청자 기본값 = 로그인 이메일)
- [ ] 같은 자재에 **진행 중인 요청이 있으면 경고**하되 등록은 진행
- [ ] 상태로 좁히기
- [ ] 요청 목록 표 + 엑셀
- [ ] 처리 버튼은 **관리자만**
- [ ] 상태 흐름: 요청됨 → 검토중 → 승인됨 → 구매중 → 입고완료 (검토중·승인됨에서 반려 가능)
- [ ] 승인 시 **수량을 고칠 수 있음**
- [ ] 반려 시 사유 필수
- [ ] 구매 처리 시 거래업체 필수
- [ ] 입고 처리는 `receive_purchase_request` RPC (재고 + 구매이력 + 상태가 한 묶음)
- [ ] 삭제는 체크박스로 확인받은 뒤
- [ ] 삭제는 `remove_purchase_request` RPC (입고완료였으면 재고 원복 + 구매이력에 취소 표시)
- [ ] 구매 이력 표 (요청을 지워도 남음)

## 7. 수리 관리

- [ ] 수리 현황 표 + 엑셀
- [ ] 상태는 저장된 값이 아니라 **보낸 수량과 반납 합계를 비교해 그때그때 계산**
      (0건 = 수리중 / 일부 = 일부 복귀 / 전량 = 복귀완료)
- [ ] 여기서 수리 건을 **새로 만들지 않음** (출고 등록 시 자동 생성됨)
- [ ] 행을 고르면 반납 등록 폼
- [ ] 남은 수량이 0이면 "이미 전량 반납" 안내
- [ ] 반납 결과: 정상복귀 / 폐기
- [ ] **정상복귀만 재고 복구, 폐기는 복구 안 함**
- [ ] 자재목록에 없는 부품(`material_id` 없음)은 재고 반영 없이 기록만
- [ ] 반납 등록은 `add_repair_return` RPC (초과 반납은 **DB가 거부** → 그 메시지를 그대로 표시)
- [ ] 회차별 반납 이력 표
